Creator Assist

Loop engineering: a system that keeps coding agents shipping approved tasks unattended

Loop engineering is building the system that runs coding agents on repeat, instead of prompting them by hand. This one picks an approved task, has an agent write it, runs eight checks, and sends the diff to an independent verifier: a different model that reads it cold. What comes back is fixed and tried again. Durable state kept outside the model’s context survives usage limits and crashes. A budget and a kill switch bound every run, risk tiers and file-boundary checks limit what it may change alone, and everything else is escalated to a person. Every design change is written down as a decision record first. The brain behind this panel is this project.

The opportunity

The agent merges only the exact commit it verified, and only onto the exact main it verified against. That strictness is what lets it merge with nobody watching. I measured a working session and saw where the time went: when main moved during a run, a change that had already passed review was being rebuilt from the start. That rework was 32% of the session.

The options I weighed

Run more agents in parallel. They share one usage limit, so the estimate was 1.2 times the output for twice the agents.
Leave it as it was. Safe, but it kept redoing the work most likely to be right: work that had already passed every gate.
Carry the finished change forward. Rebuild it on the new main, run every check again, and keep the review only if the patch itself is unchanged. Merge queues and Gerrit work the same way.

What I built

The third. The merge rule stayed exactly as strict: checks always run again on the rebuilt change, and a patch that changed goes back to the reviewer. The speed came from keeping good work, with the same gates.
