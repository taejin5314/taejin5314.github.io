Evals

I measured the reviewer before I trusted it.

Twelve real changes with 26 known defects. The loop as it was found 11, adding a second, independent reviewer found 15, and the same reviewer run twice differed by 19 points. I rebuilt the experiment as a command with a fixed answer key that the agent cannot edit.

Verification

Nothing merges on the model’s word.

Eight checks run on every attempt, then a different model reviews the diff. The checks failed 360 attempts before a reviewer saw them, and 392 of 1,436 reviews sent the change back.

The checks and the reviewer, in the brain

Guardrails

Each task has a boundary, and the agent cannot widen it.

A task names the files it may touch. 315 attempts that reached outside were rejected. Changes that add network calls or read credentials stop for a person, a change to a protected file is refused, and a kill switch stops the loop when the same failure keeps coming back.

The boundary and the kill switch

Memory

The agent writes down what it learned, and reads it next time.

A shared memory of lessons from earlier runs, searched at the start of each one. It has written 469 lessons and recalled lessons 6,772 times.

Memory, in the brain

Orchestration

One loop, durable state, and a person only when it asks.

2,161 attempts across 1,302 recorded runs. 69% of merged changes passed on the first attempt, and the median run took 9 minutes 36 seconds from start to main.

Replay any run

Workflow

The agent that wrote a change never approves it.

My own sessions with an agent follow a written playbook. The goal and the smallest change that meets it are stated first. One agent builds one unit of work. A second agent that did not write it runs the change against its parent and posts a verdict, and only a passed change merges. I added a budget of about 120 tool calls per agent after measuring that sub-agents were 86% of token use, and that four runs of 100 calls cost about a quarter of one run of 400.

Cost

A budget is part of the design.

A merged change costs about $0.61 of model usage at the median, measured over 117 runs. A run that meets a provider limit pauses and picks up later, which has happened 13 times.

Case study

A third of the agent’s time was rework. I did not add more agents.

When main moved during a run, a finished, reviewed change had to start over. I measured it first: 4 of 15 runs over two days, 32% of the session’s time.
